## Chroma and driver comparison

A documentation check requested on 2026-10-14 confirmed Razer advertises [19-zone Chroma RGB](https://www.razer.com/productivity/razer-pro-type-ergo?page=tech-specs) for this keyboard and a [Chroma app preview for macOS](https://www.razer.com/synapse-4-mac). Neither establishes a public SDK address for the small command-dial indicator. The older [SDK setup guide](https://developer.razer.com/works-with-chroma/setting-up/) and [SDK FAQ](https://developer.razer.com/works-with-chroma/chroma-faq/) describe vendor SDK components/services; their Windows-oriented examples should not be treated as a current Mac compatibility statement. On 2026-10-15 the actual Mac device maps established a shared M1–M5 zone; they do not expose independent macro-key RGB.

The installed Razer HID Driver Extension was disabled and its Virtual HID Driver Extension enabled during the successful USB getter reads. Ergo Control/helper were stopped and no restoration journal remained before asking the user to enable the existing Razer HID driver for a controlled Bluetooth-only custom-color test. The controlled test subsequently enabled both Razer extensions, but the user saw no indicator response. Fresh Razer logs show its class-6/ID-4 RGB writes rejected as Target ID Not Support, and mode 3/0 being selected. This reproduces our failure with the vendor driver enabled. Native firmware fallback is the leading explanation; there is no working custom Bluetooth dial-indicator color path from that test to capture. General Chroma support does not establish that the mode LED is a public Chroma target. No driver or Chroma package has been installed by this project, and the tool does not depend on vendor code. General custom-animation controls remain deferred; the optional Codex status adapter is implemented but needs live end-to-end validation; the built-in backlight effects added in 0.2.7 use the keyboard’s own firmware.
