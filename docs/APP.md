# Ergo Control — setup and validation

Build: `zsh tools/build_app.sh`. Application: `build/Ergo Control.app`, bundle ID `dev.local.ergocontrol.app`.

This native SwiftUI app has local profiles, app-based automatic switching, ordinary-key and extra-control assignments, configurable command-dial modes, an alternate layer, and a menu-bar control. Actions include shortcuts, timed macros, text, app launch, selected zsh scripts, scrolling, media, dial-mode cycling, and battery display.

The current app is **0.2.8**. Earlier version numbers below identify when a feature was introduced or a test was performed; they do not require installing those historical builds. The former Preview bundle was a development copy of the same app. Builds now always use `build/Ergo Control.app`; its bundle identifier, signing identity, settings, and input helper remain the same. A fresh clone builds `build/Ergo Control.app` with its own signing identity and helper, without any original installer or research evidence.

## One app for normal use

Use **Ergo Control.app**. It contains the current settings UI, menu-bar control, Bluetooth configuration, and optional input-helper installers. Ergo Probe and Ergo Bluetooth are optional developer tools kept under `build/diagnostics/`; they are not launched or needed by Ergo Control. Their sources remain available for protocol research. ErgoInputHelper is a bundled background component rather than another settings app; ErgoUSBInspector is a developer command-line tool.

The local 0.2.8/build-27 cleanup moved the known-good Preview bundle to the canonical Ergo Control path and preserved the old 0.1.1/build-2 bundle under `build/archive/` with a `.bundle-archive` suffix. Nothing from profiles, captures, recovery, or signing storage was removed. The existing helper was reused unchanged. The main build no longer accepts `ERGO_APP_NAME`; this prevents accidental duplicate product bundles.

The app has original split-keyboard/dial artwork in its Finder icon and settings header, plus a monochrome menu-bar mark that follows macOS appearance. Artwork is generated from native vector drawing code in `tools/render_icons.swift`, with PNG/ICNS assets committed under `resources`. Regenerate with `swift tools/render_icons.swift resources` before rebuilding. No Razer artwork, font, third-party image dependency, or vendor asset is bundled.

## Keyboard lighting effects (0.2.7)

Open **Keyboard lighting** and click **Read keyboard**. If disconnected, use **Connect keyboard** first. The panel offers the five built-in effects described by Razer: Off, Static, Breathing, Spectrum cycling, and Wave. Static has one color; Breathing offers random, one, or two colors; Wave offers left/right direction. Click **Apply lighting** to write the setting and read it back. **Save changes** applies to mapping profiles, independently of this device setting.

Lighting controls work with mappings off or on. The effect runs in keyboard firmware, using the existing Bluetooth connection; no new driver, helper installation, cloud account, or host animation loop is involved. Effects are global rather than tied to the selected mapping profile. Changing effects preserves backlight brightness; keep it above 0% to see the result. Stopping mappings does not undo an explicitly applied lighting setting. Persistence across a keyboard power cycle is not claimed.

Supported-effect discovery, current-effect reads, and writes share the serial configuration channel. Each write is followed by a readback; the panel reports mismatches or rejection rather than claiming success. Restoration takes priority over the next step in an effect operation. Optional command rejection does not stop working mappings. Protocol packet/parser/validation tests pass. A live Bluetooth read advertised Off, Static, and Breathing only, while the current native setting read as Spectrum cycling. Build 25 therefore offers all five known built-in effects. Spectrum/Wave show a note that they were omitted from the list; an explicit Apply attempts the recovered command and verifies readback. User testing confirmed Breathing appears to work, and live readback confirmed Static, Breathing, and Off settings. The user subsequently confirmed the combined Spectrum/Wave and steady-button test works; live readback verified Spectrum cycling plus Wave in both directions (rate 40). Build 25 queues explicit lighting clicks behind background mode/battery/brightness exchanges, so buttons do not dim during each routine check. Only an outstanding user lighting operation or a connection/restoration transition disables them. Pending clicks are canceled on disconnect or restoration. The physical dial indicator remains a separate unresolved control.

A developer-only read diagnostic is available as `ErgoControl --lighting-read`; quit other configuration apps and stop mappings first. It performs no lighting writes and refuses to run with a pending restoration journal. If restoration remains pending after a disconnect, `ErgoControl --restore-keyboard` runs the same exact-device recovery as app startup and removes the journal only after verified restoration; it does not choose an arbitrary mode.

## Keyboard brightness and dial colors (0.2.6)

Gaming mode and shortcut blocking have been removed from the UI, runtime, and saved profile model. Existing schema-1 profiles load with their mappings and custom modes preserved; the new Keyboard brightness mode is appended. Saving writes schema 2. New profiles start with Keyboard brightness. Deleting that mode from a schema-2 profile remains effective across restarts.

Set left clockwise, counterclockwise, and click to **Default** to use the command-dial modes. Select **Keyboard brightness** by clicking through the enabled modes, then turn to adjust PT Ergo’s backlight in five-percent steps. Brightness reads the actual hardware value before each batch, clamps at 0–100%, and verifies the written value by read-back. Ordered turns arriving during a command are queued for the next batch. Brightness is a user setting and remains at the chosen level when mappings stop. Each completed adjustment shows a non-activating percentage popup for two seconds; continued turns refresh it without taking focus. The user confirmed backlight control works, and hardware read-backs covered both 0% and 100%. The user also confirmed the percentage popup works.

Each mode has an experimental **Indicator color** picker for the small physical LED beneath the left dial. Physical colors are not working yet. Native operation requires keyboard backlight above 0%; the app checks actual brightness before attempting a flash, defers at zero, and retries once when brightness is raised. It never raises brightness automatically.

Tests with positive backlight still reject the recovered RGB target (class 1 / ID 39) with status 7, meaning unsupported target ID for that command. Both three-byte RGB and four-byte RGB-plus-brightness writes were rejected. Enabling the indicator first succeeds and reads back as on, but its RGB getter/setter still fail. An acknowledged on/off command does not prove physical illumination. The separate RGB-only commands return status 5 (unsupported command/class). The current preview uses bounded read-only LED inventory/type/RGB queries, preserving the literal bytes returned in the LED list. It no longer attempts the rejected color or on/off writes. These literal type/RGB queries also returned status 7. No inferred target is written. Native colors return over Bluetooth with mappings off, even while Ergo Control remains open. Driver mode replacing native dial processing is the leading explanation, but the current comparison also changes input capture. Host control of that indicator remains unresolved. A separate [USB research tool](USB_RESEARCH.md) successfully read its native stage and RGB color; Bluetooth adaptations were rejected. This does not add USB mappings or physical-color control to the app.

Earlier experimental builds saved prior light state durably before writes. Their recovery journals remain supported: stopping restores normal keyboard input mode before any owed indicator recovery. Recovery information survives disconnect/restart until restoration is verified. The current diagnostic build makes no new indicator changes to restore.

Unsupported optional commands display an error without disconnecting working mappings. Rejected indicator APIs stay disabled until restarting the app, avoiding repeated probes during ordinary use. Transport timeouts or malformed exchanges still reset the channel. The input helper is unchanged and requires no reinstall. All 70 automated tests pass; hardware-confirmed brightness and its percentage popup remain separate from unresolved physical colors. See [PROTOCOL.md](PROTOCOL.md) for evidence and [ROADMAP.md](ROADMAP.md) for deferred work.

## First setup

1. Open Ergo Control. Keep mappings off initially.
2. Grant **Ergo Control** its own **Input Monitoring** and **Accessibility** entries in System Settings → Privacy & Security. The diagnostic apps' grants do not cover this separate bundle. Input Monitoring permits reading input; Accessibility permits emitting mapped keyboard actions. The code matches only Bluetooth PT Ergo `068e:02c3`.
3. Quit Ergo Probe, Ergo Bluetooth, and the Razer Synapse/App Engine GUI before enabling mappings. The app checks these exact app bundle IDs; it does not stop services or alter drivers. The verified helper sessions used Razer’s HID Driver Extension disabled; after the controlled Razer comparison it was returned to that state. Its Virtual HID extension was already enabled and was left unchanged. Ergo Control installs a local launch-daemon helper, not a DriverKit extension, so it does not appear in the Driver Extensions list.
4. Configure a harmless M1 **Type text** action such as `Ergo test`, then save. Use the **60-second test** button for the first test. Allow the app's expected Bluetooth prompt to connect to the paired keyboard.
5. For full dial/keyboard replacement in this development build, use **Install input helper…** and complete macOS Installer's administrator authorization. Add `/Library/PrivilegedHelperTools/dev.local.ergocontrol.inputhelper` to **Input Monitoring** separately from the GUI. Reopen the app, **Refresh status**, and use **Check helper permission** with mappings off. See [INPUT_HELPER.md](INPUT_HELPER.md) if setup fails.
6. Click inside **Try your mappings** and press M1. The saved text should appear. In extra-button mode, ordinary typing and native dial/media input continue through macOS; their replacement mappings are unavailable. Check stop/quit returns the keyboard to its saved mode before daily use.

For **Command dial modes**, leave both left-dial direction mappings set to **Default** and leave left dial click at **Default**. The click cycles enabled modes. An explicit clockwise/counterclockwise action overrides that direction's current mode; the saved `CW` assignment is only the test action and should be replaced or reset for normal use. The mode popup and cycling have been user-verified.

In **Switch applications**, rotation holds Command across turns so macOS shows its native application switcher. Clockwise moves forward; counterclockwise moves backward. A one-second pause releases Command and activates the selected app. Ordinary keyboard input, another action, a profile/mode change, or stopping mappings ends the session. A physical Command key remains held until its actual release. This also applies to explicit `cmd+tab` / `cmd+shift+tab` shortcuts assigned to either dial's rotation; button and macro shortcuts remain one-shot. The timer runs during UI tracking as well as normal operation.

Under full keyboard control, **Right space**, **Split B · extra key**, and **Split Backspace · extra key** now retain their native defaults when set to **Default**. These are separate report-5 records, not ordinary report-1 key snapshots. Both halves share ownership of the generated native key: releasing one half does not release the other or stop its repeat. Physical modifiers apply to these keys, and held mappings remain latched until release. This native forwarding is limited to the exclusive full-control route; the non-seizing fallback still does not synthesize native input. The default IDs are recovered from the product's static mapping table, with live split-key confirmation pending.

To make **AI** toggle Codex, select **AI button**, choose **Show / minimize application**, select `Codex.app`, and save the mapping. The first press launches the app if necessary or brings it forward; a press while its window is frontmost minimizes that window. The next press restores the remembered window and brings the app forward. A background app is shown rather than minimized. With multiple windows, the focused/main minimizable window is used. This uses the settings app's existing Accessibility permission and the selected app's window support. Changing between Open application and Show / minimize application preserves the selected app path. No profile settings are automatically overwritten.

**Enable mappings** is the regular session control. Closing the settings window leaves the menu-bar app available. **Stop mappings** releases the keyboard and requests a read-verified mode restoration. Quit defers termination while restoration remains owed.

## Menu bar and dial-mode indicator (0.2.4)

Click the left dial with its mapping set to **Default**, or use any **Next dial mode** mapping, to cycle enabled command-dial modes. A small popup near the bottom of the display under the pointer shows the selected mode and profile for 1.5 seconds. Repeated clicks update that popup and restart its timeout. The overlay ignores mouse input and does not activate Ergo Control or take keyboard focus; stopping mappings dismisses it. Full-screen and multi-display presentation still need visual verification.

The menu-bar label now contains a keyboard icon and the keyboard's battery percentage. `—%` means the configuration connection or a battery reading is unavailable; it does not imply ordinary keyboard input is disconnected. The menu includes **Refresh battery**, the active profile/mode, mapping controls, **Settings…**, and **Quit Ergo Control**. A typed battery-percent value from the existing hardware-verified battery query supplies the label; displayed status strings are not parsed.

At launch the app requests a configuration connection to the same strictly matched Bluetooth PT Ergo and reads battery status when the channel is idle. It checks for pending work every five seconds, polls battery no more than once every five minutes, and limits automatic reconnection attempts to one per minute. Mapping preparation, a busy command, and pending normal-mode restoration take priority; a manual refresh remains pending until safe. Background polling reads configuration only and never activates mappings or changes the keyboard mode. A previously owed restoration remains handled by the existing restoration workflow. Quitting stops polling before releasing/restoring input.

`LSUIElement` and the accessory activation policy keep Ergo Control out of the Dock and normal Command+Tab application list, including while Settings is open. Close Settings for menu-bar-only operation; use **Settings…** to reopen it. Quit from the menu bar when you want to exit. This is a GUI-only update with the same helper and permissions. The signed release, helper policy check, and all 43 automated tests (including serial-channel polling priorities and throttling) pass. Native UI inspection again failed with a closed computer-use pipe. The user subsequently confirmed all three requested behaviors after reopening the preview: the dial-mode popup, menu-bar keyboard icon/battery percentage, and absence from the Dock. Full-screen/multi-display presentation and long-term battery-refresh cadence remain unverified live.

## Implementation

**Show battery (0.2.5):** with mappings enabled, the physical battery button's **Default** action and any control explicitly assigned **Show battery** use the same popup panel as dial-mode changes. Quick reads show the freshly retrieved percentage directly for two seconds. **Checking…** appears only when the read has taken more than two seconds, then is replaced by the result. It does not activate Ergo Control or open Settings. If a battery read is already running, the action shares its result; otherwise it requests a read when the serial channel is idle. Failures show **Unavailable**. A later mode popup, timeout, or stopping mappings invalidates the earlier presentation so a delayed battery reply cannot revive or replace it. Passive background battery refresh does not show a popup. The local release, helper-policy check, and all 43 regression tests pass. The user confirmed the original percentage popup works and reported a roughly half-second reading delay; the Checking delay was then adjusted at their request. The final delayed-Checking/slow-read path has not been separately verified live. The existing helper and permissions are reused.

- `ErgoCore` contains packet codecs, snapshot decoders, profile models, shortcut validation, and the macro parser.
- `ErgoDevice` contains the shared serial Bluetooth configuration controller. Neither app links or loads vendor libraries.
- `ErgoControl` contains the settings UI, profile store, action engine, and exclusive HID relay.
- The relay matches exactly one Bluetooth PT Ergo. It first attempts exclusive access; when macOS returns `kIOReturnNotPrivileged`, it opens the keyboard non-exclusively and processes only physical report 5. In this mode it never synthesizes native key, pointer, dial, or media input. It creates no global event tap and opens no other input devices.
- Extra-button mode supports M1–M5, AI, left click, battery, and their alternate-layer assignments. Custom dial modes, media replacement, ordinary-key remapping remain unavailable without full keyboard access. The UI disables unavailable controls after detecting this mode. Driver mode still changes the left dial to horizontal-pan input; stopping restores the saved normal mode.
- Version 0.2.2 uses an optional, scoped input helper for exclusive capture, with an explicit local installer and SMAppService for notarized distribution builds. The settings app remains unprivileged. The local helper is installed and its exclusive input route now works on this Mac. No Razer driver was installed or changed by this project. See [INPUT_HELPER.md](INPUT_HELPER.md) for its trust boundary and activation steps. Open results are saved in `Settings/input-status.json`, without raw key data.
- Unknown keyboard/media/report layouts stop mapping and return native input rather than silently swallowing an unsupported control. This needs hardware validation, especially for less common Fn-row/system keys.
- A renewed 60-second lease keeps driver mode active while the relay is running. Stop, quit, sleep, disconnect, and detected failures release input and request restoration. The deadline uses monotonic uptime. A durable saved-mode record supports restoration on a later launch after a process failure; the app cannot promise restoration while its process is killed or the keyboard is disconnected.
- Shortcuts are key chords. Macro text uses one shortcut per line, `wait 200` for a 200 ms delay, and `text Hello` for text. Macros allow at most 200 steps and 60 seconds of waits; only one macro runs at a time. Stopping mappings cancels pending macro work and releases generated held keys.
- Scripts run through `/bin/zsh` with the selected file as an argument, with output discarded. The app terminates its launched shell after 10 seconds; arbitrary descendant processes created by a script are outside this guarantee.

Settings are stored locally in `~/Library/Application Support/ErgoControl/Settings/profiles.json`, with an atomic write and a `.backup` of the previous version. Settings contain user-chosen app/script paths and macro text; they should not be committed to a public repository. The main app does not record ordinary typed text. Its in-app test pad is not persisted. Bluetooth transaction/recovery logs remain local under `ErgoControl/Bluetooth/`.

The earlier build used an ad-hoc signature. Version 0.2.2 uses a persistent, isolated local development certificate by default, or ERGO_CODESIGN_IDENTITY when supplied. The first signing-identity change may require refreshed macOS grants. Developer ID signing/notarization and publication are deferred; the optional helper requires separate macOS administrator authorization. Bundled Service Management registration failed for the local build; the explicit local installer, helper permission grant, and first full-control session now work on this Mac. Removal and distribution signing remain unverified.

For GUI-only development changes with an existing valid bundle, `ERGO_REUSE_HELPER=1 zsh tools/build_app.sh` preserves its helper and installer packages. Use this only when the helper/IPC code and signing policy do not need updating. The build verifies both signatures and runs the reused helper's read-only signing-policy self-check; it does not install or start a service.
