# Music app fallback

Under **Keyboard → Buttons → Music app when nothing can resume**, choose **macOS default**, **Apple Music**, or **Spotify**. The choice saves immediately and applies to PT Ergo's Play/Pause button and mappings using the Play/Pause action. It does not change global file associations or other keyboards.

The default remains the existing macOS media-key behavior. With Apple Music or Spotify selected, an existing system media target keeps Play/Pause, including a paused player. If the selected app is already running, Play/Pause always uses native routing without a target lookup. If it is closed and there is no target, Ergo Control opens it using its exact bundle identifier. Opening it does not choose a track or send another Play command. Next/Previous, volume and mute keep their existing routes. Missing apps produce a notice rather than falling back to a different app.

The experimental focus-first option remains separate and off by default. If enabled, a recognized focused/remembered accessible player still owns the command. Only its final system fallback uses the music-app choice. A focus change, mapping stop or preference change cancels an unresolved request, and ambiguous or uncertain AX actions never trigger a second global Play command.

## Compatibility and privacy

Apple's public [Now Playing information center](https://developer.apple.com/documentation/mediaplayer/mpnowplayinginfocenter) publishes the calling app's media session; it does not provide this app with the system-wide target. Explicit music-app choices therefore use a guarded, read-only MediaRemote lookup (`MRNowPlayingRequest.localNowPlayingPlayerPath`, client and process identifier). It is a private macOS interface and may change. Selector signatures are checked before invocation, and replies are reduced to available/none/unknown. No song, artist, artwork, URL, browser page or playlist metadata is inspected, logged or saved. Apps that do not register a system media target cannot be recognized by this lookup.

The lookup runs off the input/UI thread, only on an applicable Play/Pause press while the preferred app is closed, with one in-flight query and a 750 ms response deadline. Unknown/unsupported/timed-out results preserve native Play/Pause without explicitly opening the preferred app. The optional idle detector must never disable playback. Choose macOS default to retain the original system behavior; with focus-first routing off, that choice does not query the private interface. The app is opened through [NSWorkspace](https://developer.apple.com/documentation/appkit/nsworkspace/openapplication(at:configuration:completionhandler:)), without AppleScript, app Automation permission, a network API or a background polling service. Launches are coalesced while a query/launch is pending.

## Verification

Regression tests cover an already-running preferred app without a published target, repeated Play/Pause after the initial launch, a player opening during a lookup, and unknown results preserving native playback. Synthetic tests also cover absent/unknown/paused-or-playing targets, native defaults and navigation, exact app identities, single launch without a second Play command, missing apps, late query/open replies, focus changes, rapid presses, native volume/mute ownership and bounded query timeouts. All 345 tests pass (175 Core, 99 Control, 71 Device). Tests inject query/launch/event callbacks and do not start music apps or playback. A read-only probe of the real lookup on the installed macOS returned no target without reading track metadata or sending a media command.

For a live check, choose Spotify, close media sessions so there is nothing to resume, then press PT Ergo's Play/Pause button: Spotify should open and Apple Music should stay closed. Start and pause a track, then verify the same button resumes/pauses that existing session. Check a browser player and the macOS default option separately. These physical player interactions remain a user check.

## Play/Pause regression fix (2026-10-18)

The initial fallback repeatedly opened Spotify instead of controlling it: the user could start a track with the mouse but could neither play nor pause with the button. Local routing events showed every Play/Pause taking the no-target launch path. A private media-target lookup can omit a running player, so the launch decision now checks the exact preferred app process before querying and again before acting on the reply. Already-open players keep native controls regardless of published target state. Unknown lookups also keep native playback. The first cold launch still opens the app without choosing a track; subsequent presses control it normally. Physical verification of the corrected build is pending.
